# π₀.₅ maintenance contract

This integration wraps the real OpenPI configuration/factory/inference APIs.
It does not reimplement the model or normalize observations a second time.
The native model is loaded once, lazily on the first `predict` call. Importing
the adapter or listing policies does not import JAX, Torch, Transformers or OpenPI.

## Supported configurations

| Method | Native config | Observation | Raw output | Horizon |
|---|---|---|---|---|
| Gaussian FM | `pi05_libero` | LIBERO RGB base+wrist, state8, prompt | EEF delta7 | 10 |
| Δ-flow | `pi05_libero_a2a_jax_lora` | Same + raw executed history10×7 | EEF delta7 | 10 |
| Δ-flow warmup/cosine | `pi05_libero_a2a_jax_lora_warmup_cosine` | Same + raw executed history10×7 | EEF delta7 | 10 |

The Δ-flow patch adds history source construction, FM + endpoint consistency,
padding/dimension loss masking, checkpoint action-statistics aliasing for raw
history, and one-step inference. It uses JAX LoRA; it is not the separate
full-finetuned R1Lite Torch implementation. Gaussian defaults to10 Euler steps;
Δ-flow defaults to1. The pinned checkpoint/action schema must be preserved.
Do not change an existing checkpoint's10-step horizon to16 in a YAML file and
describe it as a new16-step trained policy.

This adapter deliberately rejects SONIC76/state44. The stock pinned π₀.₅ model
has a32D action capacity and the available native dataset mapping returns7D
LIBERO actions. Training G1 motion64 + hands12 needs a genuine new model-head,
data/modality configuration and checkpoint, not an output-padding trick.

## Environment and bootstrap

Keep OpenPI in its own environment rather than merging its JAX/CUDA and
Transformers requirements with ImageWAM or GR00T. After the common repository
bootstrap clones/pins OpenPI and applies the checksum-verified patch:

```bash
cd /path/to/third_party/openpi
uv sync
source .venv/bin/activate
```

The pinned upstream lock specifies JAX CUDA12 and its own Flax/Transformers
versions. Install the HumanWAM lightweight orchestration package in this same
environment when running an in-process adapter, or use the native OpenPI
WebSocket server/client from another process. Never reuse a server Python
environment by blindly upgrading shared CUDA packages.

## Adapter API

```python
from humanwam.backends.pi05 import build_policy, pad_executed_history

policy = build_policy({
    "method": "delta_flow",
    "config_name": "pi05_libero_a2a_jax_lora_warmup_cosine",
    "checkpoint_dir": "/models/pi05_libero_a2a/3560",
    "schema": "libero_eef_delta7_state8",
    "num_steps": 1,
})
past, valid = pad_executed_history(raw_already_executed_actions)
result = policy.predict({
    "observation/image": base_rgb_uint8,
    "observation/wrist_image": wrist_rgb_uint8,
    "observation/state": raw_current_state8,
    "prompt": "put the bowl on the plate",
    "past_actions": past,
    "past_action_valid_mask": valid,
})
actions = result["actions"]  # native-unnormalized finite[10,7]
policy.reset()
```

Images are RGB HWC uint8. The adapter accepts raw state/history only; native
`create_trained_policy` loads matching `assets/` normalization from the
checkpoint. Delta-flow requires JAX `params/` checkpoints. Histories contain
strictly past *executed* actions in chronological order, not previously planned
but unexecuted predictions. The adapter never invents a robot execution history.
The helper repeats the earliest available executed action for a short prefix,
exactly as the pinned LIBERO evaluation client. It rejects empty history.

For Gaussian, set `method=gaussian`, `config_name=pi05_libero`, `num_steps=10`,
and omit both history fields. Targets/future state are rejected. Raw outputs are
not clipped or silently converted into a different action space. A `reset`
delegates to the native policy if it supplies one; no planned-action cache is
maintained by this wrapper.

## Native training and serving

`build_train_command(config, source_dir, python=...)` and
`build_serve_command(config, source_dir, python=...)` return
`{"argv": [...], "cwd": "...", "env": {...}}`. Execute without `shell=True`.
Examples correspond to real pinned scripts:

```bash
python scripts/train.py pi05_libero_a2a_jax_lora_warmup_cosine \
  --exp-name libero_delta --batch-size 384 --num-train-steps 3560

python scripts/serve_policy.py --port 8000 policy:checkpoint \
  --policy.config pi05_libero_a2a_jax_lora_warmup_cosine \
  --policy.dir /models/pi05_libero_a2a/3560 --policy.num-steps 1
```

Prepare LeRobot `physical-intelligence/libero` and the native normalization
assets using OpenPI's existing scripts before training. Data repository/root
and modalities come from the named native config/LeRobot cache; there is no
invented universal `--dataset-dir` argument. `num_train_steps`, batch size and
save interval are explicit updates, not asserted epochs on an arbitrary dataset.
Only the named native configs above are supported by this maintained patch.

Native WebSocket wire format remains OpenPI's msgpack-numpy protocol; it must
not be sent to a GR00T ZMQ server or ImageWAM HTTP endpoint. The native OpenPI
server script binds all interfaces; network exposure is an operator decision.
No robot-controller command is issued by these builders/adapters.

## Existing R1Lite task releases

The following maintained models are separate checkpoint/runtime formats:

- `ZUO66/pi05-r1lite-microwave` and
  `ZUO66/pi05-r1lite-microwave-baseline` use14D absolute joint targets,
  three RGB cameras, history/horizon16, full Torch fine-tuning and their own
  checksummed release runtime.
- The single-flower models use7D right-arm absolute joint targets and their
  own paired images, tokenizer, statistics and release inference script.

Keep their original `config.json`, `manifest.json`, `runtime/`, tokenizer,
normalization statistics and published `infer_microwave.py`/`infer_flower.py`
or `infer_flower_baseline.py`. Do not load them with a LIBERO JAX config.
The unified LIBERO adapter does not claim these task releases or G1 SONIC76
have been converted to a new common model. Those released runtimes remain
usable through their documented native entrypoints.

## Validation and limits

The adapter's10 CPU tests exercise lazy native factory invocation, raw-history
pass-through without double normalization, output shapes, Gaussian history
rejection, method/schema mismatch, finite input checks, reset and native CLI
argument construction using injected native modules. These tests need NumPy,
not model dependencies. They do not claim JAX model inference, a GPU forward,
training, or robot closed-loop success has run in this integration checkout.

```bash
python -m pytest packages/humanwam/tests/test_pi05_adapter.py
```

The pinned patch also contains native OpenPI tests
`transforms_a2a_test.py`, `policy_a2a_norm_test.py`, and
`test_pi05_jax_lora.py`; run those in the bootstrapped OpenPI environment when
updating dependencies or patch contents. A new patch must pass
`git apply --check` against the pinned base first.
